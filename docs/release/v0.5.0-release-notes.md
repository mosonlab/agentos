# Anneal v0.5.0 — Developer Preview 5

This page is the release notes for `v0.5.0`, and the source text for the GitHub
Release body of the same tag.

Anneal is a local, single-operator control plane for handing scoped software
tasks to coding CLIs already installed on your own machine, and for keeping what
they did observable and durable: tasks, agents, repository and file grants,
isolated run records, provider event streams, human questions, review gates and
git delivery, in one workflow.

**What this release is for.** The same envelope as the previews before it:
evaluating Anneal on a machine you own, against repositories you are willing to
have an agent write to. It is not a production install.

## What changed since v0.4.0

The headline is a board that reads at chain level, clearer cost accounting, and
more durable merge and maintainer-deployment state:

- **Chains are aggregate board cards.** A chain occupies one card with its task
  count, progress and available actions instead of scattering every member
  across the board. Individual tasks remain available in chain and task detail.
  The aggregate card exposes activation, filtering and archival actions; it is
  not draggable. Individual task moves expose only operator-owned transitions.
- **Completed work clears itself.** DONE tasks are archived automatically after
  seven days, in batches of at most 100 tasks. A chain member becomes eligible
  only after every persisted member of that chain is DONE.
- **A chain has one deletion boundary.** `DELETE /tasks/:taskId/chain` deletes
  the chain and marker-bound repair tasks atomically, and refuses while active
  runs or retained run/session history remain. Chain members can no longer be
  deleted individually through `DELETE /tasks/:taskId`.
- **Costs explains more of the bill.** The page is rebuilt as a two-column
  dashboard with model, cache and waste breakdowns alongside period totals and
  top-run views. Aggregation reconciles the model breakdown to its total and
  fixes missing date buckets across local day and DST boundaries. The costs
  endpoint now requires an IANA `tz` query parameter and returns `400` when it
  is omitted instead of guessing.
- **Readiness and merge recovery have durable ownership.** Readiness claims use
  an explicit handle; merge-lease handoffs and deferrals are recorded in a
  durable ledger; deferred releases are indexed and retried; merge-tail requeue
  authority and budget are persisted; recovery refusals and transitions are
  applied through shared typed decisions.
- **The maintainer appliance deploys immutable releases.** Verified release
  directories are assembled before a quiet window and activated atomically
  through a stable `current` pointer. A durable ledger records build, backup,
  migration, activation, verification and rollback evidence. This does not
  change the public foreground install sequence.
- **The running build identifies itself in Settings.** The console reports the
  Anneal product version and exact build SHA returned by `/version`, separately
  from runner daemon and provider CLI versions. A failed request is reported as
  a failure rather than being presented as an unknown build.
- **The public OSS-B0 harness is removed.** `verify:oss-b0` and
  `test:oss-b0-harness` are gone as a breaking change, with no compatibility
  alias. The repository's current gate, release checks and frozen smoke fixture
  remain.
- **Two project-scoped goal aliases are removed.** Call
  `POST /goals/:goalId/approve-dod` and `POST /goals/:goalId/pause`; the former
  `/projects/:projectId/goals/...` routes no longer exist.
- **The board wire shape carries an aggregate projection.** `view=board` adds a
  `chainAggregate` field to one row in each chain. The web client uses it to
  render one card while the API retains the underlying task rows.
- **The public entry point is rewritten.** The README now leads with the
  unattended chain workflow, current board and agent views, clearer trust
  boundaries and the Linux Do community link.

The full list, by area, is in [`CHANGELOG.md`](../../CHANGELOG.md).

## Install and upgrade

There is no supported upgrade path between developer previews. This release
adds five migrations, so install fresh, following the quickstart in the
repository [`README.md`](../../README.md) — it checks out `v0.5.0`.

Do not install this release over a v0.4.0 database. The supported release path
is `npm run db:migrate:release -- --fresh` against an empty schema. The host
warnings and verification steps in the
[Developer Preview quickstart](developer-preview.md) apply unchanged.

## Support, security and licensing

The [support matrix](support-matrix.md) remains the current statement of what is
supported and on what evidence. macOS on Apple Silicon remains the only target;
Linux is unverified and Windows unsupported. Anneal still launches coding CLIs
with the operator account's authority and is not a sandbox.

The [security](security.md), [license and assets](license-and-assets.md) and
[migration and recovery](migration-and-recovery.md) documents remain current.
