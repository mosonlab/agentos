# Anneal v0.7.0 — Developer Preview 7

This page is the release notes for `v0.7.0`, and the source text for the GitHub
Release body of the same tag.

Anneal is a local, single-operator control plane for handing scoped software
tasks to coding CLIs already installed on your own machine, and for keeping what
they did observable and durable: tasks, agents, repository and file grants,
isolated run records, provider event streams, human questions, review gates and
git delivery, in one workflow.

**What this release is for.** The same envelope as the previews before it:
evaluating Anneal on a machine you own, against repositories you are willing to
have an agent write to. It is not a production install.

## What changed since v0.6.0

The headline is that Anneal now onboards a project of your own, with the
approval gates and the hold control you want rather than the ones the workflow
came with:

- **Add your own project, end to end.** `POST /projects` bootstraps a Project
  with the canonical `pr-engineer-workflow` template; the chain implements,
  reviews and applies fixes, then hands over an open pull request with its
  evidence for you to review and merge yourself.
  [Add a project](../runbooks/add-a-project.md) is the single onboarding page
  for both the pull-request tier and the full Direct and Full Assurance tier.
- **A repository is checked before Anneal accepts it.** Adding a repo runs a
  preflight over Git identity, remote reachability, default branch, fetch and
  dry-run push, and can grant every active Project Agent `GIT_WRITE` in the same
  transaction. Preflight is never skipped as a success fallback. A Repo must
  now declare `dependencyProvisioning` as exactly `NONE` or `NPM_CI`; Anneal no
  longer infers it, and a declaration that contradicts the repository's lockfile
  is refused with a named code and a remedy instead of producing a Run that
  fails later.
- **Approval gates are yours to set.** A Project carries `specGateDefault` and
  `mergeGateDefault`, and an instantiation can override either with a `gates`
  object. For the specification and merge-readiness slots the gate resolves as
  dispatch override, then project default, then the template step's own value,
  and the result is persisted onto the created Tasks, so changing a default
  later never changes a chain already running. Factory defaults leave both gates
  off.
- **Hold and resume a chain from the Board.** Chain cards carry Hold and Resume
  directly, show a held state, and can be held before the first layer starts;
  the Doing column can hold every chain it shows at once. A hold is
  layer-granular and never cancels a Run already in flight.
- **The console reads faster.** Board cards are compact, every column reads
  newest first, and a card footer links the newest Run's pull request and its
  cost. Task detail opens on the frontier step, adds a session column, a
  collapsible Details block, and a Now block carrying the newest Run's latest
  agent message. Every open Inbox card takes a free-text answer, and a gate
  decision can carry a note.
- **Costs answers what a chain cost and how long it took.** Per-chain lead and
  busy time, repair counts, longest idle gap and priced spend by step role join
  the existing totals. Waste is partitioned exactly into operator-cancelled and
  failed spend, failed spend further by failure class, and a Run whose cache
  split is unknown is excluded from cache metrics rather than folded in.
- **The host stops being oversubscribed by its own work.** The runner skips new
  claims while the one-minute load average is above cores times 1.5, Run
  verification shares a host-wide proof-slot ceiling, Node test concurrency is
  capped inside Run proofs, waits of 60 seconds or more are reported, and the
  merge gate takes half the host when it is not on a dedicated gate worker.
- **Delivered work survives what happens after delivery.** A provider stream
  that dies after delivery is accepted, a reconnect notice that names its cause
  is no longer misread as `PROTOCOL_ERROR`, and a lost merge-tail repair Run
  gets a second attempt instead of stopping the tail. Runs against a private
  repository can authenticate: the session answers git credential requests from
  the runner account's home even when the provider relocates `HOME`. A failed
  fetch reports git's own error rather than a generic retry count.
- **A large internal refactor kept behaviour where it was.** Route registration
  moved out of `app.ts` into per-prefix modules, and single owners were given to
  the runner's claim payload, run session, run outcome, delivery receipt and
  dependency-cache store, to the API's refusal-code families and Run output
  evidence, to the database's canonical sync and console wire contract, and to
  the web client's chain-control and run-liveness rules. Every native projection
  is now proved to serialize to its browser contract. These changes are intended
  to preserve their existing external behaviour.

The full list, by area, is in [`CHANGELOG.md`](../../CHANGELOG.md).

## Install and upgrade

There is no supported upgrade path between developer previews. This release
adds five migrations, so install fresh, following the quickstart in the
repository [`README.md`](../../README.md) — it checks out `v0.7.0`.

Do not install this release over a v0.6.0 database. The supported release path
is `npm run db:migrate:release -- --fresh` against an empty schema. The host
warnings and verification steps in the
[Developer Preview quickstart](developer-preview.md) apply unchanged.

## Known limitations

- There is no supported in-place upgrade from v0.6.0. Install this preview
  against an empty schema through the fresh-install path above.
- The pull-request tier stops at an open pull request. Anneal does not review or
  merge it for you, and onboarding a project does not provision a second
  workflow or create a Secret.
- The `NO_CHANGES_PRODUCED` classification fixes the misleading delivery symptom
  reported in [Issue #305](https://github.com/mosonlab/anneal/issues/305), not
  the provider-side cause. A code-producing provider can still end a successful
  session after announcing work without writing or committing it. For a manual
  Task, the final prose remains available in Session events but is not promoted
  to retry handoff output.
- macOS on Apple Silicon remains the only release-verified target. Linux and
  macOS on Intel are expected to work but have not been exercised there;
  Windows is unsupported by design.
- Anneal still launches coding CLIs with the operator account's authority and
  is not a sandbox.
