## Round-8 contradiction resolution

Not a review round and it closes no finding. Reviewed head `2684de8d73f2839229fd8dda617537c1dcf38e48` on branch `agentos/chain/w2-2026-08-17-goal-5a0-p-06fa0ea4` (PR #94), against base `a4a4ba36c116c775d5d1c28ed55b17600869d904`. The final review of that head returned **FAIL** with four must-fix findings and two contradictions. Under the standing rule, must-fix findings are carried into the implementation task brief rather than reopening the artifact; a **contradiction** is the single exception, because it is a defect no downstream implementer can resolve by following the document. Only the two contradictions are resolved here, and in each case the underlying mechanism was already sound — only the normative text disagreed with itself.

**C1 — signal semantics. The artifact both guaranteed and denied that a supervisor-only `SIGINT` stops the run.**

- Text A (kept): `docs/plans/goal-5a0-idempotent-execution-kernel-plan.md:999-1004`, `:1074`, `:1084`, `:1471` — the background-child-plus-explicit-`wait` shape removes the supervisor-only-`SIGINT`-to-success defect, and every path on which no handler runs still stops.
- Text B (removed): the same plan at `:1086`, reproduced in the runbook list at `:604` and in the consequential-edits narrative at `:1478`, and repeated in the round-7 graft note at `docs/reviews/2026-08-17-goal-5a0-plan-review.md:379` — a `SIGINT` delivered only to the supervisor PID may still be discarded, permitting an honest run to reach success.

**Resolved in favour of text A, by execution.** An isolated reproduction of the documented new shape — checks launched as a background child, supervisor blocked in an explicit `wait` — was sent `INT` on the supervisor PID alone with a five-second check in flight: the handler was entered (`HANDLER:INT`) and the session exited `1` **one second in**. The same signal against the superseded round-6 foreground-child shape did not reach the handler until that child had run to completion five seconds later, which is precisely the deferral window in which a POSIX shell discards the pending signal. Text B was **measured against the superseded shape and is falsified against the specified one**; it was carried over by mistake. It is deleted from both documents, and each site is marked as a round-8 correction with round 7's claim named rather than silently erased, keeping the round-7 disposition convention.

**C2 — task-ID length. The artifact imposed a 64-character cap while three times claiming it asserts no length.**

- Text A (removed): the grammar `^[A-Za-z0-9_-]{1,64}$` at plan `:851`, `:860`, `:1107`, and reproduced at `:604`, `:657`, `:1317` and at review `:382`, with values outside it `MALFORMED_TASK_ID`.
- Text B (kept, and now true as written): "no length is asserted at any layer" / "asserting no length at all" at plan `:852`, `:1474` and review `:382`.

The cap was chosen against because it can strand a legitimate future task ID permanently: a 65-character ID that AgentOS issues and can retrieve would be rejected as malformed, holding issue #98 forever despite byte-equality being provable — the exact fail-dead class every round of this review has been about. The character class alone preserves the URL-safety property the cap stood in for (no scheme, host, path separator, query, or whitespace), and retrieval, not the grammar, proves identity. With the bound gone the "no length is asserted" statements are true as written and needed no edit.
