1. **[Correctness / Feasibility; Risk; §4.7 and §6] A failed tool-settings PATCH leaves the optimistic restriction displayed as if it were saved.** `AgentToolsCard` seeds `lastSeed` from the server value and refuses to resync when the incoming serialization is unchanged (`apps/web/src/pages/Agents.tsx:249-268`). It optimistically mutates `denied`, but on rejection only stores the error and calls `onSaved`; it never rolls back the local set (`apps/web/src/pages/Agents.tsx:270-288`). An independent JSDOM probe made the Bash PATCH return 500, rerendered the confirmed server value `disabledTools: []`, and printed `{"persistedDisabledTools":[],"renderedState":"unchecked","renderedCount":"7/8","errorVisible":true,"onSavedCalls":1}`. The server therefore allows Bash while the operator-facing switch and count say it is denied. The existing rapid-toggle test exercises only two successful 200 responses (`apps/web/src/tests/agent-tools.test.tsx:82-138`). **Remedy:** on rejection, restore the last confirmed server set (or track an acknowledgement/version that permits an unchanged server payload to reseed local state), then serialize any subsequent queued intent from that confirmed base. Add a 500-path test asserting the switch and count revert and a queued-after-failure test asserting final convergence.

2. **[Correctness / Feasibility; Risk; §4.4, §4.5, and §6.1] The mounted runner row does not age to `Unknown` when polling is suspended.** The 60-second cutoff is evaluated only when `runnerSummary(payload, new Date())` runs during a React render (`apps/web/src/components/runner-status.tsx:29-31,85-88`). `usePoll` skips every interval while `document.hidden` and has neither a visibility-change handler nor a timer that causes a freshness render (`apps/web/src/lib/hooks.ts:41-63`). Consequently, a tab hidden after a green response can return displaying the already-rendered green `Running` DOM until some later request changes state; if that request hangs, the stale state persists. The only freshness test calls the pure helper directly with an already-old timestamp (`apps/web/src/tests/runner-status.test.tsx:73-75`), so it cannot catch the mounted transition required by “It never shows a stale Running” (`docs/specs/batch-1-settings-i18n.md:389-395`). **Remedy:** schedule a local freshness invalidation and handle `visibilitychange` so the row recomputes before/when the page becomes visible, independently of request completion. Add a mounted fake-timer test that begins green, hides the document beyond 60 seconds, restores visibility with a failed or unresolved fetch, and observes grey `Unknown` immediately.

3. **[Scope; Coherence / Quality; §4.3 and §7] The Chinese UI is not fully localized, and the acceptance guard cannot detect the remaining English.** The Chinese dictionary deliberately renders the human-facing tab `Capabilities` unchanged (`apps/web/src/locales/zh.ts:84-90`), despite the spec allowing English only for proper nouns, identifiers, and API data (`docs/specs/batch-1-settings-i18n.md:175-190`). More broadly, runner preferences are generated as raw lowercase enum values outside the dictionaries in the model picker (`apps/web/src/components/model-picker.tsx:81-86`) and Goals form (`apps/web/src/pages/Goals.tsx:68-73`), so Chinese Custom flows display labels such as `inherit` and `auto` even though enum-shaped human labels explicitly require keys. The dictionary tests check only key sets, non-empty values, and placeholders (`apps/web/src/tests/i18n.test.tsx:16-38`), while the AST sweep scans source literals but not whether `zh` is actually Chinese (`apps/web/src/tests/i18n-sweep.test.tsx:125-130`). Real browser inspection in Chinese reproduced English `Capabilities`/runner labels in the UI; a dictionary comparison also returned `agents.tab.capabilities=Capabilities` as an identical alphabetic English/Chinese pair. **Remedy:** translate non-technical user copy, add dictionary keys for each human runner preference, and use `t()` at all human-label call sites. Add a small justified allowlist for proper nouns/technical identifiers, reject other alphabetic `en === zh` dictionary values, and render representative Chinese pages/forms to assert that raw enum labels do not escape.

1. **[Scope; Coherence / Quality; §4.2 and §6.5] The full Settings Runner card drops required status emphasis.** The spec calls for an online/offline dot, a separate `Busy` badge, and destructive tone below 2 GB (`docs/specs/batch-1-settings-i18n.md:159-173,389-396`). `DaemonDetails` instead renders a plain translated state value and an unstyled disk string inside `KeyValue` (`apps/web/src/pages/Settings.tsx:18-32`). Browser checks confirmed the Settings card is readable in light and dark, making this a survivable presentation defect rather than missing telemetry. **Remedy:** reuse a shared state indicator in Settings, render Busy as a badge distinct from online state, apply destructive tone to disk below 2 GB, and add Settings-specific assertions for all three cues.
