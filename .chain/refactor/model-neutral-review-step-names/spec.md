Templates: review steps are named for what they do, not for the model that runs them

Goal: the three canonical templates name their two review steps "Code review" and "Blind code review", so the label stays true whichever agent a staffing profile assigns to them.

Background: step display names come from `stepNames` in `packages/db/src/template-sources.ts` and are today "Code review (Sol)" and "Code review (Opus blind)". Since Staffing Profiles (2026-09-05) any agent can be staffed on either step, so a name that carries a model is a lie the moment a profile changes it. A step's name is part of the structural shape that `canonical-template-transition.ts` uses to identify a template generation, so this rename is a structural rollover, not a prompt edit: on the next deploy canonical sync must recognise the rows every installation holds now, rename them under a legacy marker, install the new graph, and remap staffing profiles onto it. `agents/README.md` "Changing a canonical prompt" states the three-part procedure and names the merge-gate test that refuses a generation nothing can transition from. Instantiated chains keep their stored step names; only template rows change.

Changes:
1. In `template-sources.ts`, for `direct-engineer-workflow`, `compound-engineer-workflow` and `pr-engineer-workflow`: "Code review (Sol)" becomes "Code review" and "Code review (Opus blind)" becomes "Blind code review". Output kinds (`sol-findings`, `blind-findings`), step prompts, layers, optional flags and agent bindings are unchanged.
2. For each of the three templates, the outgoing generation is registered in the retired-generation registry in `canonical-template-transition.ts` with one marker naming this change (the same marker for all three), the shape the deployed rows hold today, and no `promptDigest`; the published-generation entries are annotated as the README procedure for a shape change requires. `CANONICAL_SOURCE_PROMPT_GENERATIONS` changes only if `npm run db:template-digest` says the digests changed (prompts are untouched, so they should not).
3. `canonicalTemplateIdentity` resolves the new legacy names to their template and generation, and `CURRENT_CANONICAL_STEP_ORDINALS` and repair routing still address the renamed steps.
4. A dbtest seeds a project holding the three templates in today's shape with a staffing profile that staffs the blind step, runs canonical sync, and asserts: the old rows are renamed under the new marker, the new rows carry the new step names, the profile's entries survive on the same output kinds, and the sync report counts the rollover with no refusal.
5. Every other reference to the old names follows: `agents/README.md`, `docs/BRIEF-TEMPLATE.md`, `docs/operator-api.md`, and the tests that assert the names (`template-sources.test.ts`, `canonical-template-registry.test.ts`, `packages/api/src/templates.test.ts`, `specification-fidelity.test.ts`, `template-authoring-replace.dbtest.ts`, `merge-integrator-seed.dbtest.ts`, `scripts/operator-api-docs.test.mjs`). Retired-generation shapes in the registry keep the old names, because they describe rows that exist.

Out of scope: renaming output kinds or the `.md` prompt files; any prompt text change; agent bindings or the optional flag; the web console; pruning or hiding legacy template rows (a separate chain handles the Workflows list); the `legacyTemplateName` helpers in `merge-integrator.ts` (a separate chain handles the registry ownership).

Constraints: the published-generation list is append-only and nothing rewrites its last element; no digest is invented by hand, only copied from `npm run db:template-digest`; a generation that cannot be transitioned from must fail in the merge gate, never at deploy; existing instantiated tasks keep their stored names and prompts.

Acceptance: `npm run test -w @anneal/db` passes including `canonical-published-generations.test.ts`, the registry tests and the new rollover dbtest (dbtests run in the merge gate); `npm run test -w @anneal/api` passes; `npm run lint`, `npm run typecheck` and `npm run test:snapshot-scan` pass; `git grep -n 'Code review (Sol)\|Code review (Opus blind)'` returns hits only inside the retired-generation shapes of `canonical-template-transition.ts` and the tests that assert those retired shapes; `npm run db:template-digest` output matches `CANONICAL_SOURCE_PROMPT_GENERATIONS`.
