Every route of the control plane is registered inline inside `createApp` in `packages/api/src/app.ts`, so any chain that adds or changes an endpoint rewrites that one file; after this chain each route prefix lives in its own module and `app.ts` only assembles them.

Background: On main `79f46fd6`, `packages/api/src/app.ts` is 3409 lines: ~220 lines of imports, ~590 lines of zod schemas and helpers (`refusal`, `refusalJson`, `validated`, `resolveTaskChain`, `readJson`, ...), and `createApp` (line 808 onward), which builds the CORS, origin and principal middleware and then registers every route as an inline closure, in prefix order: system (`/`, `/health`, `/version`, `/runners`, `/hooks`, `/files`, `/onboarding`), `/projects` + `/environments` + `/secrets` + `/projects/:id/costs`, `/agents` with grants/skills/mcp/repos, `/goals`, `/task-templates` + `/triggers` + fire, `/tasks`, `/inbox`, `/runner/*`, `/session/*`, `/sessions` + `/runs`, then `onError`/`notFound`. The domain logic behind the handlers already lives in sibling modules (`templates.ts`, `run-claim.ts`, `run-completion.ts`, `board.ts`, `inbox.ts`, `task-patch.ts`, ...); what remains in `app.ts` is HTTP shape: parsing, validation, refusal mapping, and the call into the module. Of 200 PRs merged since 2026-08-17, 80 touched `app.ts` and 37 touched `app.test.ts` (2592 lines, 79 tests), making them the most shared write surface in the repository; chains that touch `app.ts` are serialized at dispatch time for that reason. The closure inventory shows the split is clean: only six `createApp`-local values are used by more than one prefix group (`app`, `releaseChainLease`, `runners`, `noteArchivedQueuedRunsOnClaim`, `preflightRecoveryLeases`, `preflightRecoveryIntervalMs`), and only 10 of the 82 module-level helpers are shared across groups (`refusal`, `refusalJson`, `id`, `readJson`, `validated`, `readBoundedBody`, `FILE_WRITE_LIMIT`, `fileErrorResponse`, `secretPublicSelect`, `taskOutputInput`); every other schema and helper is used by exactly one group. Hono matches routes in registration order, and at least one existing test depends on it (`/inbox/messages/summary` must be registered before `/inbox/messages/:messageId`). Hono 4.13 exposes the registered table as `app.routes` (`{ method, path, handler }[]`).

Changes:
1. Create `packages/api/src/routes/` with one module per prefix group: `system.ts`, `admin.ts` (projects, costs, environments, secrets), `agents.ts` (agents, secret grants, filesystem grants, collaborators, skills, mcp connections, repos and repo access), `goals.ts`, `tasks.ts` (every `/tasks` and `/projects/:projectId/tasks*` route), `inbox.ts`, `runner.ts` (every `/runner/*` route), `session.ts` (every `/session/*` route plus `/sessions*` and `/runs/*`). Each exports a single `register<Group>Routes(app, deps)` function. The `/task-templates`, `/triggers`, `/hooks/templates` and `/task-templates/:templateId/fire` routes stay in `app.ts` in this chain (see Out of scope).
2. Move each route handler verbatim into its group module together with the zod schemas and helpers that only that group uses. The handler body, status codes, refusal reasons and response shapes do not change; the diff for a moved handler is a relocation, not a rewrite.
3. Put the shared values in one module, `packages/api/src/routes/support.ts`: the ten shared module-level helpers named in Background, the `AppEnvironment` type, and a `RouteDeps` type carrying `db`, `options`, and the `createApp`-local values that more than one group reads (`releaseChainLease`, `runners`, `noteArchivedQueuedRunsOnClaim`, `preflightRecoveryLeases`, `preflightRecoveryIntervalMs`). Values used by exactly one group are constructed in that group's module or passed only to it, not widened into `RouteDeps`.
4. `createApp(db, options)` keeps its exported name and signature. After the change it constructs the middleware exactly as today, builds `RouteDeps`, calls the register functions in the same prefix order the routes have today, keeps the remaining template/trigger routes inline, and installs `onError`/`notFound`. Within each group the registration order of routes is preserved.
5. Add a route-table test in `packages/api/src/app-routes.test.ts` that builds the app through `test-app.ts` and asserts the ordered list of `${method} ${path}` pairs from `app.routes` (middleware entries excluded) equals a literal expected list captured from main before the move. The list is the specification of the move: the chain records it from the pre-change `app.ts` first and the post-change app must reproduce it exactly, including order.
6. Split `packages/api/src/app.test.ts` along the same groups into `packages/api/src/routes/<group>.test.ts`, moving each test verbatim to the module whose routes it exercises. Tests that exercise the app boundary rather than one group (public root, principal token rejection, runner/operator principal separation, CORS and origin allowlist, unknown view refusal, validator headers on polled collections) stay in `app.test.ts`. The total test count across `app.test.ts` and the new files equals the count on main before the move.
7. Update `packages/api/src/index.ts` and any other importer only if the import path of a moved symbol changed; `createApp` itself continues to be imported from `./app.js`.

Out of scope: the `/task-templates`, `/triggers`, `/hooks/templates` and fire routes and their schemas (the template authoring chain 9f5b5fab is rewriting them; they move in a follow-up after it merges); any change to handler behavior, validation rules, status codes, refusal reasons, response shapes, or middleware order; moving logic out of handlers into domain modules; renaming or reordering routes; introducing controller classes, decorators, dependency injection containers, or a generic router abstraction; changes to `packages/api/src/test-app.ts` beyond what an import path requires; changes to any file outside `packages/api`; changes to the `dbtest` suites; changes to the operator API documentation (no route changes, so none is needed).

Constraints: every route module receives its dependencies through the `RouteDeps` argument and imports nothing from `app.ts` (no circular import). Shared helpers move to `support.ts` once; no helper is duplicated into two group modules. A handler that fails to type-check after the move is fixed by importing the same symbol it used before, not by loosening a type. The `Route:` parsing, template instantiation, and every sibling logic module are untouched.

Acceptance: `app-routes.test.ts` passes with the literal table recorded from main before the move, and the table contains every route currently registered in `app.ts` (the count equals the number of `app.get|post|patch|put|delete(` registrations on main at the chain's base). `packages/api/src/app.ts` is under 700 lines. `grep -c "app\.\(get\|post\|patch\|put\|delete\)(" packages/api/src/app.ts` counts only the template/trigger/hook/fire routes. No file under `packages/api/src/routes/` imports `../app.js`. The sum of tests in `app.test.ts` plus `routes/*.test.ts` equals 79 (the count on main `79f46fd6`, re-recorded at the chain's base if it moved). `npm run lint`, `npm run typecheck -w @anneal/api`, and the `@anneal/api` unit and dbtest suites are green.
