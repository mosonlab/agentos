A runner can ingest every valid session event containing NUL characters without losing its lease, and event-delivery failures can never prevent heartbeat renewal.

Background: executeClaim buffers session events and appendEvents sends them to POST /runner/runs/:runId/events, where the API persists them with sessionEvent.createMany. PostgreSQL rejects U+0000 in text values with 22P05. A rejected event batch is retried indefinitely, while the runner heartbeat loop currently awaits flushEvents before sendHeartbeat, so event ingestion failure can starve lease renewal and cause reconciliation to mark healthy work LOST.

Changes:
1. Normalize every literal U+0000 before SessionEvent persistence in all persisted event string fields, including recursively nested payload strings plus providerEventId and toolCallId, replacing each NUL with the visible six-character sequence \u0000 while preserving every other character, event cardinality, seq value, and batch order.
2. Renew the run heartbeat independently of event delivery: the heartbeat attempt must occur before event flushing, and an appendEvents failure must not suppress later heartbeat attempts. Preserve the existing budget, fencing-token, lease-expiry, and HTTP 409 stop semantics.
3. Make the runner event-write queue recover after append failure. The failed batch must remain retryable in original seq order; after the endpoint recovers, pending events are accepted once under the existing skipDuplicates idempotency contract, and later flush attempts are not permanently poisoned by a prior rejected promise.
4. Add API and runner coverage for literal NUL ingestion, mixed valid/NUL batches, repeated event-endpoint failure spanning at least two heartbeat intervals, recovery with ordered delivery, and the existing 409 fencing behavior.

Out of scope: Prisma schema or migrations; stall/reconciliation policy; provider adapter output formats; delivery-lease design; claim-poll isolation; retry-budget policy; changing merge automation; swallowing or reclassifying non-NUL persistence errors.

Constraints: Do not silently drop events or fall back to degraded behavior. NUL normalization must be deterministic, visible, and limited to persisted string values; non-NUL inputs must remain byte-for-byte equivalent at the string level. Heartbeat and event delivery must retain their independent errors and current fencing authority. Tests must use a throwaway RUNNER_WORKSPACE_ROOT and scratch PostgreSQL only.

Acceptance: (1) an API test posts events containing literal NUL values in nested payload strings, providerEventId, and toolCallId and reads back the visible \u0000 representation with unchanged seq ordering; (2) a scratch-PostgreSQL db test persists a mixed batch without 22P05 and reads back the same event count and order; (3) a runner test makes the events endpoint fail across at least two heartbeat intervals, observes successful heartbeat attempts throughout, then restores the endpoint and observes exactly-once ordered persistence under skipDuplicates; (4) existing HTTP 409 heartbeat/fencing coverage remains green; (5) the targeted @agentos/api and @agentos/runner suites pass, followed by scripts/merge-gate.sh --expect-head <exact candidate oid>.
