A repeatable public operator path exists for provisioning and maintaining the self-hosted GitHub App merge executor.

Background: The repository ships the fail-closed merge executor, its environment contract, and acceptance-evidence scripts, but it has no authoritative setup runbook or repeatable wizard. A public user cannot install mosonlab's private App and must register an installation-local GitHub App. The executor also refuses startup unless its private key is file-backed under a dedicated OS identity distinct from API/model-runner peers. Without a public procedure, users must reverse-engineer permissions, identity custody, service management, verification, upgrade, and recovery from source.

Changes:
1. Add docs/runbooks/merge-executor.md as current public authority. It must explain the self-created private GitHub App model; selected-repository installation; no OAuth, Device Flow, webhook, or event subscriptions; the recommended permission set (Administration read, Checks read, Commit statuses read, Contents read/write, Merge queues read/write, Metadata read, Pull requests read/write, Workflows read/write); and map every permission to the executor's actual REST/GraphQL operations, distinguishing mandatory access from workflow-file support.
2. Add scripts/setup-merge-executor.sh from the canonical wizard template with the library above STAGES byte-for-byte unchanged. Its stages must guide only the human-owned GitHub UI and credential/config capture journey, use hidden input for secrets, validate public identifiers and owner-only key metadata without printing key bytes, preserve mode 0600 for secret-bearing output, refuse placeholders/aliasing/same-user peer configuration, and finish with exact next commands. It must not silently skip a failed prerequisite or perform an unannounced privileged action.
3. Document supported macOS LaunchDaemon and Linux systemd service profiles: dedicated non-admin OS identity, root-owned runtime/start/config, owner-only key, explicit executable paths, restart-at-boot behavior, API/executor token separation, and why no passwordless sudo or generic root helper is installed. Human-only administrator steps must be explicit and separately confirmed; the wizard must not imply they happened when it only printed instructions.
4. Document post-install verification, first positive App-bot merge evidence, regular health via /runners, key/token rotation, App-key recovery, and code upgrades for a root-owned executor runtime. State clearly that the repository auto-deploy build may update the serving checkout's merge-executor dist but does not itself adopt that build into a separately root-owned service runtime.
5. Link the runbook and wizard from the appropriate public README/setup surface and keep .env.example comments consistent with the runbook. All examples must use placeholders and portable paths; no mosonlab installation IDs, local user paths, tokens, or private operator procedures may enter tracked files.
6. Add deterministic tests that statically trace every wizard-captured value to its documented destination, assert secret inputs are never echoed, assert the required permission and isolation checklist is present, and make bash -n plus the new tests runnable without GitHub access, root, launchd, systemd, or real credentials.

Out of scope: changing the live mosonlab GitHub App, current production services or credentials, credential rotation, making a public multi-tenant App, relaxing executor isolation, adding passwordless sudo or a reusable root helper, changing auto-deploy adoption semantics, fixing merge re-authorization, or modifying PR #44/#46.

Constraints: Public repository content only; fail loudly with named errors; no degraded fallback; no secret material in argv, logs, fixtures, snapshots, or test output; GitHub UI instructions must link official GitHub documentation and separate stable concepts from UI labels that may drift. The wizard skill's template library is immutable. Existing .env values remain authoritative on rerun unless the human explicitly replaces them.

Acceptance: bash -n scripts/setup-merge-executor.sh passes; the new deterministic wizard/runbook test suite passes without network or privilege; npm run test -w @agentos/merge-executor passes; scripts/verify-secret-hygiene.mjs passes; README and .env.example link/variable checks pass; repository-wide merge gate passes for the exact final head; review confirms every documented GitHub permission has a named source operation and every actual mutating operation has documented required permission and verification evidence.
