A merge gate that is not running on a gate worker sizes itself to half of the host by default, so an agent-invoked gate on the shared runner host no longer claims every core and its matching memory.

Route: implementation=senior-dev - a one-line default change in a bash script whose only risk is a wrong precedence between the worker's explicit export and the new default; the unit suite can witness it fully.

Background: This brief targets `origin/main` at `75ea468446df55fd60c564bcae1f38f13dc0f782`, verified with `git rev-parse origin/main` on 2026-09-01. The host resource audit of the same day (records/AUDIT-host-resources-20260901.md) found the production host memory-bound: 16 GB RAM, 4.6 GB of 6 GB swap in use, 1.7 TB swapped out since boot. The largest single burst per Run is an agent running `scripts/merge-gate.sh` inside its run workspace on the shared host. At the pinned SHA the script sizes itself from `GATE_HOST_SHARE="${AGENTOS_GATE_HOST_SHARE:-1}"` (`scripts/merge-gate.sh:1058`), accepts only `1` or `2` (`:1059-1062`), derives `GATE_CPUS = availableParallelism() / GATE_HOST_SHARE` (`:1063-1066`), and from that `GATE_UNIT_LANES` and `GATE_DB_LANES` (`:1081-1082`). On the 10-core host the default is therefore 10 unit lanes and 10 database lanes for one gate, beside nine other runners, the API, postgres and a desktop session. The script's own comment (`:1070-1078`) records that these widths were measured on a dedicated worker and that running the waves together on a 4 GiB worker turned passing suites into timeouts for memory reasons.

The gate worker does not rely on the default: `scripts/gate-worker/run-gate.sh:208` exports `AGENTOS_GATE_HOST_SHARE="$WORKER_CAPACITY"` before invoking the gate, and docs/runbooks/gate-worker.md:35 and :445-447 document that the worker's share is the only sizing input it passes. An explicit environment value must keep winning; only the absent-variable case changes. Chain L2 (8458563f, records/BRIEF-affected-workspace-proof-20260901.md) separately stops Runs from invoking the full gate at all through the shared prompt paragraph and AGENTS.md; this brief does not touch AGENTS.md, adapters, agents/roles or any canonical prompt, and it must land regardless of L2 because operators and pre-merge checks still invoke the gate by hand on this host.

No test at the pinned SHA exercises the host-share default: `git grep -n HOST_SHARE origin/main -- scripts/*.test.mjs` matches only `scripts/gate-worker/gate-worker.test.mjs`, which tests the worker's export, not the gate's default. `scripts/merge-gate-parallel.test.mjs` (467 lines) is the existing source-adjacent Node `test` file for the gate's parallel sizing and is where the new assertion belongs.

Changes:
1. In `scripts/merge-gate.sh`, change the default at line 1058 from `1` to `2`: `GATE_HOST_SHARE="${AGENTOS_GATE_HOST_SHARE:-2}"`. Keep the accepted values `1` and `2`, the fail-loud message for anything else, and the derivation of `GATE_CPUS`, `GATE_UNIT_LANES` and `GATE_DB_LANES` exactly as they are. Update the comment block above it so it states the new rule in one sentence: absent variable means half the host, because the shared runner host is where an unset value is observed; a gate worker always exports its own share.
2. Update the `note "host share: ..."` line only if its wording would otherwise print a stale claim; the printed fraction already comes from `GATE_HOST_SHARE`, so this is expected to need no change.
3. Add one test in `scripts/merge-gate-parallel.test.mjs` that runs the sizing fragment (or the script's existing test hook for it, whichever the file already uses) three ways: variable unset yields `GATE_CPUS = floor(availableParallelism() / 2)` (minimum 1); `AGENTOS_GATE_HOST_SHARE=1` yields the full count; an invalid value such as `3` fails with the existing message. If the test file has no way to run the fragment in isolation, add the smallest extraction the file's existing style already uses; do not restructure the script.
4. In docs/runbooks/gate-worker.md, adjust the sentence at :445-447 only if it states that the gate's own default is the whole host; the worker behaviour it describes is unchanged. If any file under `docs/` changes, `npm run test:snapshot-scan` must stay green.

Out of scope: AGENTS.md, packages/runner/src/adapters/*, agents/roles/*, any canonical prompt (owned by chain L2); the worker's `run-gate.sh` and its capacity export; the values `GATE_UNIT_LANES` and `GATE_DB_LANES` derive to for a given `GATE_CPUS`; the tmpfs size or container flags of the gate's postgres; any new environment variable, detection of "am I on a worker", or reading of load or memory; runner or API code.

Constraints: An explicit `AGENTOS_GATE_HOST_SHARE` continues to win over the default in every case. Fail loudly on an invalid value exactly as today. No new dependency, no new knob, no new observability surface. Production change is one line plus its comment; tests and one runbook sentence at most.
