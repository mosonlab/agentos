Runner: The runner's admission, restore and PATH mechanisms work on Linux as well as macOS

Every host-side mechanism the runner owns — the host proof slot, the dependency-cache restore and the child PATH — works on Ubuntu as it does on macOS, so a control plane and its Codex runners can move to a Linux host without a per-host patch.

Route: implementation=senior-dev - the host proof slot is a lock-ownership window whose two candidate tools disagree on the meaning of the same option letter (lockf's `-s` is "silent", flock's `-s` is "shared"), so a plausible translation admits every Run into one slot simultaneously and every existing admission fixture still passes.

Background: This brief was researched against `main` commit `9a52c6ada5cea5a309e53d87912dd33c5249fae5` on 2026-09-03. Every citation below was read on that commit; locate them by name if lines shift. It is a sibling of `BRIEF-gate-dispatch-local-slots-20260903.md`, which owns gate dispatch capacity and touches none of the files named here; the two chains can land in either order.

The host proof slot is the runner's host-wide admission gate for build, lint, typecheck and test inside a Run. `scripts/host-proof-slot.sh:59-68` opens the slot file read-only on descriptor 9, then calls `/usr/bin/lockf -s -t 0 9`; the lock is taken on the open file description, so it survives `lockf` exiting and is held for the life of the child (`scripts/host-proof-slot.sh:56-58,72-74`). The scan loop treats exit 75 — lockf's `EX_TEMPFAIL` — as "this candidate slot is held" and every other non-zero status as a setup failure that must stop admission (`scripts/host-proof-slot.sh:212-219`), and the wrapper refuses to admit at all when `/usr/bin/lockf` is not executable, exiting 64 with a named message (`scripts/host-proof-slot.sh:169-172`). `/usr/bin/lockf` is a BSD utility: it exists on macOS and does not exist on Ubuntu, where the equivalent is util-linux `flock(1)`. The two tools are not option-compatible. lockf's `-s` means silent and its lock is always exclusive (`man 1 lockf`); flock's `-s` means *shared*, and an exclusive non-blocking lock is `-x -n`. flock also carries `-E, --conflict-exit-code`, which sets the status returned when a non-blocking lock is refused, so `75` can be produced at the source rather than translated by the wrapper — the wrapper's `75` contract, its child-status passthrough (`scripts/host-proof-slot.sh:78-81`) and the fixture that proves a child's own exit 75 is preserved (`scripts/host-proof-slot.test.mjs:275-287`) then need no change at all. The runner's own coordination proof hard-codes the same absolute path and skips itself when it is absent (`packages/runner/src/host-proof-slots.test.ts:57-96`), so on Linux the only test that proves two unrelated principals serialise on one slot inode would silently not run. `scripts/host-proof-slot.test.mjs` — the wrapper's own suite, wired as the root script `test:host-proof-slot` (`package.json:32`) — is not invoked by `scripts/merge-gate.sh`, so nothing runs it automatically today.

The dependency cache restores a published entry by copying it into the Run workspace: `packages/runner/src/dependency-cache.ts:508-511` uses `cp -c -R` on Darwin and `cp -a --reflink=always` elsewhere. `--reflink=always` fails on a filesystem without reflinks, and ext4 has none; the failure is not an integrity error, so it propagates out of `restoreEntry` and out of `materializeWorkspaceDependencies` (`packages/runner/src/dependency-cache.ts:612-623`) and fails provisioning on every cache hit. No fixture catches it: the hit test intercepts the copy command and copies with `node:fs` (`packages/runner/src/dependency-cache.test.ts:121-124`), and the only case that runs a real clone probes support first and skips when there is none (`packages/runner/src/dependency-cache.test.ts:191-207,1328-1331`). `scripts/merge-gate.sh:291` already uses `cp -a --reflink=auto` on Linux for the same job, so the runner holds the last `always` in the repository.

The runner's default child `PATH` and the API's controlled Git `PATH` both begin with `/opt/homebrew/bin` (`packages/runner/src/config.ts:134`; `packages/api/src/git-launch.ts:1,7`), duplicated as a literal in two packages and published as an active assignment in `.env.example:73` and as documentation in `docs/release/developer-preview.md:231-233`. `scripts/setup-local.mjs` never writes `RUNNER_PATH`, so on a fresh Linux install the compiled default is what a runner child gets. No test pins either literal.

Two adjacent things were checked and need no change. The Codex session-config provisioning copies the runner account's Codex credential file into the session root with the absolute `cp` and `chmod` binaries under the run-as prefix, writing mode 0600 into a 0700 root (`packages/runner/src/adapters/session-config.ts:52-120`, reached from `packages/runner/src/adapters/codex.ts:250-257`); nothing on that path is macOS-specific, and every absolute `/bin` tool it names resolves on Ubuntu. Whether the isolated accounts can traverse the runner account's home to read that file is a host provisioning condition, not a code one. The second is `packages/runner/src/adapters/runtime.ts:464-466`, whose `ps` arguments are already platform-branched.

Changes:
1. Select the host proof slot's lock tool by platform in `scripts/host-proof-slot.sh`: `/usr/bin/lockf` on macOS, `/usr/bin/flock` on Linux. The Linux invocation must take an exclusive, non-blocking lock on the already-open descriptor 9 and must report contention as exit 75 through flock's conflict-exit-code option, so the scan loop's `75`-means-held test and its "any other status is a setup failure" rule (`scripts/host-proof-slot.sh:212-219`) remain unchanged and no status translation is added anywhere. flock's `-s` is a shared lock and must not appear. The executable precondition (`:169-172`) must name the selected tool, keep exit 64, and keep the message shape `<tool> is not executable`; an unrecognised platform is a refusal, never a default to one of the two tools. Selection must add no process, stat, or file touch to the host fast path (`:8-18`).
