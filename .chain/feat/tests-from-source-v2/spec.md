Runtime package resolution is the remaining cause. `@anneal/db` exposes nine entry points whose `types` targets are source and `import` targets are `dist` (`packages/db/package.json:8-44`); `@anneal/runner` does the same for four subpaths (`packages/runner/package.json:6-22`), and `@anneal/github-client` for its root (`packages/github-client/package.json:8-13`). `@anneal/build-info` already exports its source-owned `index.mjs` rather than a built copy (`packages/build-info/package.json:6-10`); API, Inbox, and Merge Executor are executable workspaces with no package exports. TypeScript uses `NodeNext` resolution (`tsconfig.base.json:5-6`) and already selects the source `types` targets, so no `customConditions` change is required. On the production host's Node 26.8.1, `--conditions=development --import tsx` loads `.ts` ESM directly; the lockfile pins `tsx` 4.23.12 (`package-lock.json:5831-5844`). Conditional-export key order is material: `development` must precede the always-matching `import` condition.

Tests currently invoke Node through `tsx`, but lifecycle builds hide runtime resolution (`packages/api/package.json:9-12`; `packages/runner/package.json:27-28`; `packages/inbox/package.json:9-10`; `packages/merge-executor/package.json:9-13`; `apps/web/package.json:9-10`). A parent Node condition is not inherited in `process.execPath` argv. L3's landed `runNodeTest` constructs a fresh child argv and spawns it with the supplied environment (`packages/api/scripts/dbtest.mjs:64-68` on `origin/main`; the run-scope-guard branch it was cited from is merged), and the API source ownership suite separately spawns `index.ts` and its probe (`packages/api/src/control-plane-ownership.test.ts:404-420,587-665`). By contrast, the Runner's children in `regression-verification-script.test.ts:72-75,115-119`, `adapters.test.ts:111-133,763-812`, and `run-output.test.ts:415-431` execute inline JavaScript, shell fixtures, or relative Runner source and do not resolve another workspace package; they need no new production-like behavior.
