Every Anneal Run has a self-contained platform regression toolset that operates against its assigned repository checkout.

Route: implementation=senior-dev - the acceptance suite cannot witness the cross-module run-time tooling contract between runner materialization and gate worker dispatch.

Background: The canonical regression steps still invoke `scripts/regression-verification.sh` from the checked-out repository. That script requires `AGENTOS_WORKSPACE_PATH`, but at lines 33, 36, and 39 it derives `SCRIPT_ROOT` from its own repository location and uses that root to find `scripts/gate-worker/gate-dispatch.sh` and `lib.sh`. `scripts/gate-worker/gate-dispatch.sh:174-182`, `mirror-push.sh:116-130`, and `remote-gate.sh:144-148` similarly find their companion `lib.sh` through `SCRIPT_DIR`, while the `REPO_ROOT` assignments at `gate-dispatch.sh:175`, `mirror-push.sh:117`, and `remote-gate.sh:145` assume the scripts live two levels below the repository root. These assumptions prevent the platform scripts from running as a bundle outside an arbitrary Project checkout. `gate-dispatch.sh:325-332` already locates `mirror-push.sh` and `remote-gate.sh` beside itself, and `lib.sh` is repository-independent.

The runner creates each checkout in `provisionWorkspace` in `packages/runner/src/workspace.ts`, then `executeClaim` in `packages/runner/src/runner.ts` creates a per-Run `AgentScratch` with `provisionAgentScratch` before adapter preflight and provider launch. `buildChildEnvironment` in `packages/runner/src/adapters.ts` is the common child-environment constructor: it currently exposes `AGENTOS_WORKSPACE_PATH` to every Agent session at line 157, while only regression steps receive the conditional chain/base variables at lines 163-166. `workspaceEnvironment` in `packages/runner/src/adapters/environment.ts` supplies the narrower runner-owned environment used during workspace and scratch operations and has no per-Run tooling path. The runner package build in `packages/runner/package.json` currently emits TypeScript and a build stamp only. Release snapshots recursively inventory `packages/runner/dist` through `RELEASE_SNAPSHOT_OUTPUTS` in `scripts/deploy/release-snapshot.mjs`; source-built deploy artifacts also require that directory through `DEPLOY_REQUIRED_ARTIFACT_PATHS` and `deployReleaseArtifactPaths` in `scripts/deploy/release-artifacts.mjs`, and `buildReleaseArtifact` in `scripts/deploy/release-artifact.mjs` runs the root build before assembling the immutable release. Therefore generated content under runner `dist` reaches both cached and source-built releases without a second deploy-only copy path.

Changes:
1. Keep the five files under `scripts/` as the canonical sources and add a runner-package build action that recreates `packages/runner/dist/runtime-tools` from them without transforming bytes. The generated layout is `runtime-tools/regression-verification.sh` plus `runtime-tools/gate-worker/{gate-dispatch.sh,lib.sh,mirror-push.sh,remote-gate.sh}` and contains no other file. A missing source, copy failure, or byte mismatch fails the runner build. This option leaves the repository paths present for the currently deployed templates while eliminating a tracked second copy that could drift. Because the generated tree is inside `packages/runner/dist`, both release-snapshot publication/materialization and the final deploy artifact include it through their existing recursive runner-dist inventories.
2. Add a `toolsDir` inside each `AgentScratch.base`, as a sibling of `workspaceRoot` and `stateDir`, and materialize the release-local `dist/runtime-tools` tree there for every Run after scratch creation and before session configuration, adapter preflight, or provider launch. The destination is a fresh `tools` directory outside `workspace.path`; create it exclusively rather than merging with or overwriting an existing entry. Materialization produces exactly the five regular files and the one required `gate-worker` directory, with both directories mode `0700` and all five files mode `0500`, including under `runAsPrefix` so the launched account owns and can execute/read them. Any collision, absent artifact, wrong file type, permission failure, or partial copy is a Run-start failure; normal scratch cleanup removes the materialized tree.
3. Name the new platform-owned variable `AGENTOS_TOOLS` and set it to `scratch.toolsDir` in the unconditional portion of `buildChildEnvironment`, after task Secrets, so a Secret cannot redirect it. It must reach every model-executed step and all Claude, Codex, and Pi start/resume launch paths, including launchers that scrub their inherited environment. Do not add it to `workspaceEnvironment`, whose callers run before a child session has a materialized `AgentScratch`.
4. Make the canonical scripts location-independent while preserving their existing commands and verdict behavior. In `regression-verification.sh`, replace `SCRIPT_ROOT` with the directory containing that file and resolve `gate-worker/gate-dispatch.sh` and `gate-worker/lib.sh` relative to it; this works identically in the repository `scripts/` layout and the generated/materialized layout. In `gate-dispatch.sh`, `mirror-push.sh`, and `remote-gate.sh`, replace only the three `../..` repository-root derivations named above with a required, canonicalized `AGENTOS_WORKSPACE_PATH`; reject an unset, nonexistent, or non-directory value before any Git, push, SSH, or gate action. Companion scripts and `lib.sh` continue to resolve from each script's own directory, and child dispatch processes inherit the same workspace variable. There is no fallback to a repository copy or to a path inferred from the shipped script location. Operators who run these scripts by hand from a checkout now supply the variable themselves: update every documented invocation of `gate-dispatch.sh`, `mirror-push.sh`, `remote-gate.sh`, and `regression-verification.sh` in `docs/runbooks/gate-worker.md` and `CONTRIBUTING.md` to the form `AGENTOS_WORKSPACE_PATH="$(git rev-parse --show-toplevel)" scripts/gate-worker/<script> ...`, changing only those command lines and the sentence that introduces them.
5. Extend the focused runner, adapter, gate-dispatch, build-artifact, release-snapshot, and release-directory tests needed to prove the new build, materialization, environment, and shell contracts. Fixtures must cover both the generated/materialized tooling path outside the checkout and the unchanged repository-path command used by the deployed regression templates.

Out of scope: changes to either canonical regression template step; `DEFENSE_EXACT` changes; removing any repository copy of the five scripts; documentation consolidation beyond the command-line updates named in Change 4; adding or changing the reference `merge-gate.sh`; dependency provisioning from chain C; any change to `scripts/merge-gate.sh`, `scripts/gate-worker/run-gate.sh`, `scripts/gate-worker/provision.sh`, or worker-side installation; changes to gate capacity, transport, verdict, attestation, merge authorization, or release activation semantics.

Constraints: D1 is add-only: repository paths and template invocations remain usable until D2 switches them. The build output and each per-Run materialization are byte-for-byte copies of the same five canonical files, never independently maintained variants. `AGENTOS_WORKSPACE_PATH` is the sole repository-root input for the shipped shell path. A Run must not reach adapter preflight or provider launch unless all five files are present with the required modes; missing tooling is never repaired from the checkout, skipped, or silently degraded. Materialization must not write anywhere under the checkout and must not change its Git status or HEAD.
