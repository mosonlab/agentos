Legitimate per-workspace verification inside Anneal Runs shares a host-wide concurrency ceiling while host and Regression verification retain their current behavior.

Route: implementation=senior-dev - a locking bug could deadlock or starve every Run on the host, which unit tests witness only under simulation.

Background: This brief is validated against `origin/main` commit `461cd08b028e6d42aded05fdec8919fcdbad52f4`, which includes PR #369 (`8de2dd5fab680b621f8a7c6f3d657606df1e524c`) and its follow-up fixes. On 2026-09-01 seven chains ran simultaneously on the 10-core, 16 GB production Mac and the 1-minute load average reached 120; over seven days, 232 of 832 Runs (28%) were platform-made reruns. A Run gets a fresh mirror-backed checkout and APFS-cloned `node_modules`, but `dist/` is ignored and TypeScript incremental compilation is disabled. Runtime package exports still point at built JavaScript, for example `@anneal/db` maps `types` to `src` and `import` to `dist` (`packages/db/package.json:6-43`), so tests trigger cold upstream builds: API `pretest:db` builds four workspaces before `test:db` (`packages/api/package.json:9-12`).

L3 mechanically refuses only repository-wide root commands: its six prefixes are in root `package.json:14-20,40-41`, while `scripts/run-scope-guard.sh:6-17` admits the exact `AGENTOS_RUN_SCOPE_BYPASS=regression-verification`. Per-workspace verification remains legitimate and currently unbounded. The exact script surface is the existing `build`, `typecheck`, `test`, and `test:db` entries in `apps/web/package.json:6-10`, `packages/api/package.json:6-12`, `packages/build-info/package.json:12-14`, `packages/db/package.json:46-52`, `packages/github-client/package.json:14-17`, `packages/inbox/package.json:6-10`, `packages/merge-executor/package.json:6-10`, and `packages/runner/package.json:24-28`; no workspace currently defines `lint`.

The slot directory cannot live in per-Run scratch: `provisionAgentScratch` creates a new `agentos-run-scratch-*` root for each session (`packages/runner/src/workspace.ts:197-235`). The real `RunnerConfig.workspaceRoot` is shared (`packages/runner/src/config.ts:27-57,79-110`), and OS-isolated installs provision it once as owner plus `agentos-runners`, mode 1770, so every distinct `runAsPrefix` account can traverse it (`scripts/os-isolation/provision.sh:189-227`). `buildChildEnvironment` already publishes Run identity and per-Run roots (`packages/runner/src/adapters.ts:133-170`), and `launchAdapterArgv` explicitly carries protected variables through a scrubbing launcher (`packages/runner/src/adapters/runtime.ts:252-275`). Therefore the runner, not a prompt or a fixed `/tmp` convention, can publish one path derived from the shared real workspace root.

Use persistent slot files locked through `/usr/bin/lockf` file descriptors. `flock(1)` is Homebrew-only on this host; `lockf(1)` ships with target macOS, waits silently, preserves the child exit status, and the kernel releases its lock when the last inherited descriptor closes. That provides stale-holder recovery even across different UIDs without parsing `kill -0`'s indistinguishable cross-account `EPERM`, PID-reuse heuristics, or a racy delete-and-steal protocol.
