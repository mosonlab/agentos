Inside an Anneal Run, the run-scope guard, the host proof slot and the merge gate's in-Run refusal can no longer be switched off by an agent setting one documented environment variable, and every workspace has a lint entry point so an in-Run agent can lint what it changed.

Route: implementation=senior-dev - an authority boundary whose failure mode is an agent quietly disabling three guards at once; the acceptance suite cannot witness what a shell driven by a model will try, so the reviewer must reason about the caller check itself.

Background: This brief is based on `origin/main` at `d2314b91b02937b88b9af22279cfae122a3efe61`. Three guards trust the same forgeable string. `scripts/run-scope-guard.sh:10-12` exits 0 when `AGENTOS_RUN_SCOPE_BYPASS` equals `regression-verification`; `scripts/host-proof-slot.sh:16-18` takes the no-slot fast path on the same value; `scripts/merge-gate.sh:169-172` skips its in-Run refusal on it. The value is set legitimately by the runner-provided `packages/runner/runtime-tools/regression-verification.sh` around its gate dispatch. It is also printed for every in-Run reader in `CONTRIBUTING.md:52-56` and `docs/runbooks/add-a-project.md:268-269`, and `AGENTS.md` sends in-Run agents to `CONTRIBUTING.md`. Production `SessionEvent` rows show the value used 69 times by the regression verifier and 21 times by other roles, including `AGENTOS_RUN_SCOPE_BYPASS=regression-verification scripts/merge-gate.sh` from a senior-dev step (card cmtjd7hr705e1mp60l7ukw0ry, Sol verification 2026-09-02).

All Run processes share one uid, so no unforgeable capability exists; the requirement is to stop the bypass being a documented one-liner and to bind it to the process that is supposed to hold it. Separately, the root `lint` script is guarded (`package.json:17`) while `lint:biome` and `lint:types` (`:18-19`) are unguarded whole-repository scripts, and no workspace `package.json` defines `lint`, so the instruction to lint only the affected workspace cannot be followed; `scripts/host-proof-slot.test.mjs:501-517` currently pins that absence.

Changes:
1. Remove the bypass value and the statement of how to bypass from every agent-facing document: `CONTRIBUTING.md`, `docs/runbooks/add-a-project.md`, `AGENTS.md` if present there, and any template or role Markdown under `agents/` that repeats it. The documents keep the facts an in-Run agent needs: root scripts refuse with 78, the direct gate refuses with 76, and the Regression step owns repository-wide proof.
2. In `scripts/run-scope-guard.sh`, `scripts/host-proof-slot.sh` and the in-Run refusal in `scripts/merge-gate.sh`, accept the bypass only when the variable is set and the invoking process chain includes the runner-provided regression tooling: walk parent process ids and require an ancestor whose command line names `regression-verification.sh` under the directory given by `AGENTOS_TOOLS`. Any other caller with the variable set is refused exactly as if it were unset, and the refusal message names the caller's command line so the SessionEvent records the attempt. Keep the host fast path (no `AGENTOS_RUN_ID`) free of any new process or stat.
3. Guard `lint:biome` and `lint:types` with `scripts/run-scope-guard.sh` the same way `lint` is guarded, and add a `lint` script to every workspace under `apps/*` and `packages/*` that runs Biome and the type-aware ESLint rule over that workspace only, wrapped by `scripts/host-proof-slot.sh` like the other per-workspace proof scripts. Update `scripts/host-proof-slot.test.mjs` so it requires the workspace `lint` scripts instead of pinning their absence, and update `CONTRIBUTING.md` to describe `npm run lint -w <workspace>` as the in-Run lint path.
4. Extend `scripts/run-scope-guard.test.mjs` and `scripts/host-proof-slot.test.mjs` with cases where the variable is set by a caller that is not under the regression tooling (refused, exit 78 or the slot path taken, audit line present) and by a caller whose ancestor is a `regression-verification.sh` under `AGENTOS_TOOLS` (accepted). Extend `scripts/gate-worker/gate-worker.test.mjs` or the merge-gate fixtures with the same pair for the in-Run refusal (76 with `GATE NOT RUN`).

Out of scope: `packages/runner/runtime-tools/regression-verification.sh` and everything else under `packages/runner/runtime-tools/` (another chain edits those files; this chain only reads the parent command line), `packages/runner/src/**`, `packages/db/**`, `packages/api/**`, `packages/runner/scripts/build-runtime-tools.mjs`, Biome or ESLint rule sets, the proof-slot count, and any change to what the Regression step itself runs. Do not add a runner-issued token, a lease, or a new environment variable.

Constraints: Fail loudly: a refused bypass prints its reason to stderr and exits with the existing code; the host path outside a Run is unchanged and pays no new cost. The parent-process walk must fail closed (unreadable process table means refusal). Lint semantics are unchanged: a workspace `lint` must flag exactly the findings the repository-wide `lint` flags for that workspace's files.
