Malformed merge-gate OID arguments are rejected as usage errors without emitting a verdict about any commit.

Route: implementation=senior-dev-luna - This is a two-call-site contract correction with focused behavioral coverage and no cross-module migration.

Background: The standalone repository gate already distinguishes usage errors from gate judgments: `EXIT_USAGE` is 2, `EXIT_FAIL` is 1, and `die_usage` prints an error plus usage before exiting with the usage status (`docs/repo-contract/merge-gate.sh:6-15`). The parser uses that path for missing values and unknown arguments (`docs/repo-contract/merge-gate.sh:17-25`). However, `normalise_oid` rejects values that are not exactly 40 hexadecimal characters, and both post-parse validation call sites currently send that rejection to `fail_gate` (`docs/repo-contract/merge-gate.sh:29-30`, `docs/repo-contract/merge-gate.sh:50-55`). Consequently, a malformed `--expect-head` or `--master` value exits 1 and emits `MERGE GATE: FAIL`, even though no repository state or test result has been judged.

The canonical onboarding contract says malformed or incomplete usage exits 2 without a verdict (`docs/runbooks/add-a-project.md:314-319`), while its wire table assigns status 1 and `MERGE GATE: FAIL` to command or precondition failures (`docs/runbooks/add-a-project.md:321-330`). That prose is already correct. The direct reference test reads and executes the standalone gate (`scripts/repo-contract-merge-gate.test.mjs:16-18`, `scripts/repo-contract-merge-gate.test.mjs:59-75`), but its combined precondition test currently preserves the contradiction by expecting malformed `--master` to produce a FAIL verdict (`scripts/repo-contract-merge-gate.test.mjs:181-190`). The same file already has `assertNoVerdict`, which rejects both `MERGE GATE` and `GATE NOT RUN` wire lines (`scripts/repo-contract-merge-gate.test.mjs:105-113`), and a missing-value usage test that also proves the repository command does not run (`scripts/repo-contract-merge-gate.test.mjs:146-154`).

Changes:
1. In `docs/repo-contract/merge-gate.sh`, classify failure of `normalise_oid` for both `--expect-head` and `--master` as usage failure by routing the existing error messages through `die_usage`. Preserve the accepted OID grammar, lowercase normalization, messages, and all subsequent repository preconditions.
2. In `scripts/repo-contract-merge-gate.test.mjs`, keep the full-length but mismatched `--expect-head` case as a status-1 precondition failure, separate it from malformed input, and add focused malformed-value coverage for both OID flags. Each malformed case must assert status 2, no `MERGE GATE` or `GATE NOT RUN` verdict anywhere in combined output, and no execution of the repository-specific test command.
3. Leave the already-correct malformed-usage and wire-format prose in `docs/runbooks/add-a-project.md` unchanged so the implementation, executable proof, and published contract agree without editorial churn.
