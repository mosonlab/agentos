After a gate failure, the gate-fix repair task names the failing test files and the first failing assertions instead of only the failed stage names.

Background: `scripts/regression-verification.sh finalize` runs the remote gate through `gate-dispatch.sh`, captures its output in a temp file (`GATE_LOG`), reads the `MERGE GATE: FAIL (...)` proof line, and builds the persisted verdict with `summary` set to the text inside the parentheses (`json_verdict`, around line 96); the temp log is deleted on exit (line 42). `openMergeTailRepair` in `packages/api/src/merge-tail-actions.ts` puts that summary verbatim into the repair task description ("Repair the autonomous merge tail failure at <head> against target <base>." followed by the summary). On the 21 gate-fix repairs of 2026-08-24..31 the summary was only stage names such as `unit tests (all workspaces)` or `database tests (db + api), unit tests (all workspaces)`; no failing file or assertion reached the repair agent, which therefore has to rerun the whole stage to locate the failure, and the operator has no per-file record of what breaks at the gate (gate-fix is the larger half of the repair loop: 17 of 47 chains in that window). The verdict schema (`packages/db/src/merge-tail.ts`, `gate-fail` variant) requires `summary` to be a non-empty string and carries `gateProof`; it imposes no upper bound.

Changes:
1. In `scripts/regression-verification.sh`, when the gate verdict is FAIL, derive a bounded failure excerpt from the gate log: every line naming a failing test file or assertion (node:test `not ok` lines and their `# Subtest`/file context, `AssertionError` lines, `Error:` lines that follow a `not ok`), de-duplicated, capped at 40 lines and 4000 bytes, in log order. If the gate log carries no such line for a failed stage (the worker did not forward per-test output), the excerpt says so explicitly for that stage (`<stage>: no per-test output in gate log`) rather than being silently empty.
2. Persist the excerpt in the `gate-fail` verdict as a new field `gateFailureExcerpt: string` alongside `summary`; `summary` stays the stage list and `gateProof` stays the proof line, so every existing reader is unaffected. Extend the verdict validator in `packages/db/src/merge-tail.ts` to accept the field when present and reject a non-string value; its absence remains valid for verdicts written before this change.
3. In `openMergeTailRepair` (`merge-tail-actions.ts`), render the excerpt in the gate-fix repair description directly under the summary line, under a heading `Gate failure excerpt`, verbatim. Review-fix and refresh-conflict descriptions are unchanged.
4. Determine and state in the implementation summary whether `gate-dispatch.sh` / `remote-gate.sh` forward the failing step's test output into the dispatcher's stdout. If they do not, forward the failing step's last 200 lines from the worker (bounded), so that item 1 has input; if they already do, no change there.

Out of scope: any change to gate steps, lanes, or the gate verdict line format; retrying or classifying failures as flaky; changing what the review-fix or refresh-conflict repairs receive; storing the full gate log; changes to the regression-verifier role prompt or template step prompts (the script owns transcription, the agent does not write the verdict); the merge-tail state machine and lease handling.

Constraints: the excerpt is bounded in both lines and bytes so a runaway log cannot inflate a task description; extraction never changes the PASS/FAIL outcome or the proof line; a missing or unparsable gate log still fails loudly exactly as today.

Acceptance: a unit test for the extraction (shell or node, matching the existing test style under `scripts/`) feeds a fixture gate log with two failing node:test files and asserts the excerpt names both files and their first assertion, is capped at 40 lines, and reports `no per-test output` for a failed stage without such lines; `packages/db` verdict validation tests accept a `gate-fail` verdict with and without `gateFailureExcerpt` and reject a non-string one; a `packages/api` test for `openMergeTailRepair` asserts the gate-fix description contains the `Gate failure excerpt` heading and the excerpt text, and that review-fix and refresh-conflict descriptions are byte-identical to before; `npm run lint`, `npm run test:gate-worker`, and the `@anneal/db` and `@anneal/api` unit suites are green.
